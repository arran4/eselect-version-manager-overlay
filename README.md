# eselect-version-manager-overlay

Gentoo Portage overlay for [eselect-version-manager](https://github.com/arran4/eselect-version-manager). Portage installs packages; the version manager selects among installed toolchains.

**Status:** the initial `app-eselect/eselect-version-manager-0.1.0` ebuild is staged for the first source release. Until `v0.1.0` exists and a matching generated `Manifest` is committed, this is **not yet a published installable version**. No source archive or Manifest should be invented to conceal that.

## Configure and sync with Portage

As root, after installing `dev-vcs/git`, add `/etc/portage/repos.conf/eselect-version-manager-overlay.conf`:

```ini
[eselect-version-manager-overlay]
location = /var/db/repos/eselect-version-manager-overlay
sync-type = git
sync-uri = https://github.com/arran4/eselect-version-manager-overlay.git
auto-sync = yes
masters = gentoo
```

Run `emaint sync -r eselect-version-manager-overlay` for an initial clone or a manual refresh. With `auto-sync = yes`, ordinary `emaint sync --auto` also includes this overlay. No background daemon or auto-installation is required. Read [Portage repository sync documentation](https://wiki.gentoo.org/wiki/Project:Portage/Sync).

The accompanying [source project's Docker demo](https://github.com/arran4/eselect-version-manager/blob/main/docs/containers.md) preconfigures the same Git sync URI. Its build-time CI checkout is pinned for reproducibility, while an administrator can explicitly sync the overlay within a running container.

## Layout

- `app-eselect/eselect-version-manager/`: staged ebuild and Gentoo metadata.
- `metadata/`, `profiles/`: normal overlay metadata.
- `tests/portage-overlay/`: **CI-only** synthetic slotted and unslotted packages and *mock* `dev-lang/go` ebuilds. Never register this fixture directory as an overlay on a real Gentoo machine: its fake Go binaries are not Go backports.

## Package website and validation

The searchable [GitHub Pages site](https://arran4.github.io/eselect-version-manager-overlay/) is **generated by [g2](https://github.com/arran4/g2)** and deployed using the GitHub Actions Pages workflow on `main`; set **Settings → Pages → Source: GitHub Actions**. A PR builds the site without publishing it.

The overlay validation workflow performs shell/layout checks and uses G2 to lint ebuilds and repository metadata. Before the first release, the only permitted missing Manifest exception is the unpublished source archive; that exception must be removed once the real tagged distfile exists.

Locally (with [G2](https://github.com/arran4/g2) installed):

```sh
g2 overlay site generate -out site_out -clear .
g2 lint repo -fail-severity error .
g2 manifest verify .
```

The latter two commands require actual release Manifests; CI uses an explicitly documented temporary exception until they exist. G2 is a static inspector and website generator, not a substitute for Portage's real `emerge` and `ebuild manifest` checks.

## Verified toolchains versus fixtures

The fixture Go packages return canned strings. Genuine co-installable Go and Node.js packages require separately validated ebuilds ([Go #2](https://github.com/arran4/eselect-version-manager-overlay/issues/2), [Node #3](https://github.com/arran4/eselect-version-manager-overlay/issues/3)). Gentoo already slots Python and Maven; prefer those existing packages and selectors.

Release `Manifest` files are generated with Portage or an appropriately verified G2 command and **must not be hand-edited**. [Issue #4](https://github.com/arran4/eselect-version-manager-overlay/issues/4) tracks producing a real release ebuild/Manifest from a tagged source archive and proving installation.
